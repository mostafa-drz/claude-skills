Copy-paste recipes for turning the screenshots scattered across your machine into a memory you can actually query. Every snippet below is a real command — click Copy and paste it into Claude Code.

01Create the store

Run once. Creates a local git repo for your memory and verifies it has no remote — this store holds pictures of your screen, so it must never be pushable.

/screenshots-memory setup
Why the no-remote check is permanent. The skill re-runs it before every sync. If a remote ever appears, it stops and tells you rather than committing another screenshot. That's the trade that makes storing full-resolution captures reasonable.

02First sync — start narrow

Every screenshot is a vision read, so don't point it at five years of Desktop on day one. Take a week first and see how it reads your apps.

/screenshots-memory sync --since 7d

You'll get a plan before anything is read — how many it found, how many it already knows, roughly how much it will process. Reply go, or narrow it further.

03Sweep the Desktop

The everyday move. No path means the inbox — ~/Desktop by default.

/screenshots-memory sync
It only ever touches actual screenshots. Inbox discovery asks Spotlight for kMDItemIsScreenCapture == 1, so a folder, a PDF, or a photo you saved to the Desktop is invisible to it. Originals move into the store only after the commit lands.

04Ingest a folder you filed by hand

Point it anywhere. An explicit path accepts any image — a photographed whiteboard, a saved product shot — because pointing at it is a deliberate choice.

/screenshots-memory sync ~/Desktop/course-captures --yes

05Ask the memory

Plain language. Filters in the question are honoured — dates, kinds, apps, people.

/screenshots-memory what did Slack ask me to do last week
/screenshots-memory products I saved in August
/screenshots-memory everything from the Claude skills course

Answers cite the captures they stand on, and say so when they lean on something read at low confidence.

06Browse visually

Re-renders every cluster and opens the browser. Chips filter and union, so clicking product and ui shows both.

/screenshots-memory clusters

07Use the memory as input to something else

The store is a documented contract, so another skill or agent can build on it — flashcards from course captures, a board from chat ones.

Read ~/screenshots-memory/memory.json, take every note with kind: course
from the claude-skills cluster, and make flashcards from the concept and
definition fields.
Two rules for anything reading this store. Honour sensitive: true — those notes have no text on purpose. And respect confidence/reviewed: an unreviewed 0.6 is fine to surface with a caveat, poor to assert as fact.

08Turn a week of chat captures into actions

chat captures carry who, ask and due — they're usually work, not notes.

/screenshots-memory everything with a due date I haven't dealt with

09Teach it your screen

This is the part that compounds. Fix a bad read once and it stops being wrong.

/screenshots-memory review

With more than a handful flagged it sends you to the browser instead: flip ⚠ Needs review, correct cards against the actual image, then Copy for Claude and paste the batch back:

/screenshots-memory review --apply
What it learns. Corrections land in corrections.md; recurring patterns get promoted into extraction-guide.md, which the extractor reads on every sync — that the dark sidebar with # channels is your Slack, that "ABI" is a client and not a typo. Both are plain Markdown. Edit them directly if you'd rather just tell it.

10Add a kind of your own

The four shipped kinds won't cover everything you screenshot. When something doesn't fit, it proposes a kind rather than dumping it in other — and you can write one yourself.

open ~/screenshots-memory/kinds.md

A heading, a one-line description, a field table. Picked up on the next sync, no config step.

Where your data lives. ~/screenshots-memory/ — a git repo you own, with no remote. notes/ one Markdown file per capture, clusters/ rendered views, assets/ the screenshots themselves, plus corrections.md, extraction-guide.md and kinds.md. Every sync is a commit, so anything can be diffed or reverted. Nothing leaves your machine.
