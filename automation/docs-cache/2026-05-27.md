### Skill structure
- Every Skill requires `SKILL.md` with YAML frontmatter (`name`, `description` required).
- `name`: max 64 chars, lowercase letters/numbers/hyphens only; no XML tags; no reserved words "anthropic" / "claude".
- `description`: non-empty, max 1024 chars, no XML tags. Must state both what the skill does and when to use it.

### Three-level loading model
- **Level 1 (Metadata)**: Frontmatter always loaded at startup (~100 tokens per skill). Claude uses description for fuzzy-match triggering.
- **Level 2 (Instructions)**: SKILL.md body loaded when skill is triggered (<5k tokens).
- **Level 3 (Resources)**: Bundled files (scripts, reference docs) loaded only as needed.

### Where skills work
- **claude.ai / Desktop**: custom skills uploaded as zip; individual user only (not org-wide).
- **Claude API**: workspace-wide; requires beta headers `code-execution-2025-08-25`, `skills-2025-10-02`, `files-api-2025-04-14`.
- **Claude Code**: filesystem-based (`~/.claude/skills/` or `.claude/skills/`); no API upload needed.

### Runtime environment (claude.ai / Desktop)
- Network access varies by user/admin settings.
- No guaranteed shell or code execution environment — skills should not assume `bash` is available in Desktop context.
- Google Workspace, web search, and sandboxed code execution available via integrations.

### Pre-built skills available
