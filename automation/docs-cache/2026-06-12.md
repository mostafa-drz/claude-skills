### Key sections

#### Why use Skills
Skills are reusable, filesystem-based resources providing domain-specific expertise: workflows, context, and best practices that transform general-purpose agents into specialists. Unlike prompts (one-off conversation-level instructions), Skills load on-demand and eliminate the need to repeatedly provide the same guidance.

#### Three-level progressive loading

| Level | When loaded | Token cost | Content |
|-------|-------------|------------|---------|
| 1 — Metadata | Always (startup) | ~100 tokens per Skill | `name` and `description` from YAML frontmatter |
| 2 — Instructions | When triggered | Under 5k tokens | SKILL.md body |
| 3 — Resources/Code | As needed | Effectively unlimited | Bundled files and scripts executed via bash |

#### Required frontmatter fields

```yaml
---
name: your-skill-name     # max 64 chars, lowercase letters/numbers/hyphens,
                          # no XML tags, no reserved words "anthropic"/"claude"
description: >-           # non-empty, max 1024 chars, no XML tags
  What the skill does and when Claude should use it.
---
```

#### Where Skills work
- **Claude Code**: filesystem-based at `~/.claude/skills/` (personal) or `.claude/skills/` (project). Full network access.
- **claude.ai**: upload as zip via Settings > Features; individual per user. Varying network access.
- **Claude API**: uploaded via `/v1/skills`; shared workspace-wide. No network access.

#### Runtime constraints (Claude Code)
Full network access. Avoid global package installation.

#### Runtime constraints (claude.ai)
Varying network access depending on user/admin settings.

#### Security
Only use Skills from trusted sources. Malicious skills can invoke tools or execute code unexpectedly.
