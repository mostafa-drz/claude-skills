## platform.claude.com/docs — Agent Skills Overview (captured in full)

Key sections relevant to skill authoring:

### Skill structure (required)

```yaml
---
name: your-skill-name          # max 64 chars, lowercase + hyphens only, no "anthropic"/"claude"
description: >-                # non-empty, max 1024 chars, no XML tags
  Brief description and when to use it.
---
```

**Required fields**: `name` and `description` only. All other frontmatter (allowed-tools,
disable-model-invocation, etc.) is Claude Code-specific and does not apply to Desktop skills.

### Three loading levels

| Level | When Loaded | Token Cost |
|-------|-------------|------------|
| Metadata (frontmatter) | Always, at startup | ~100 tokens per skill |
| Instructions (SKILL.md body) | When skill triggers | Under 5k tokens |
| Resources (bundled files) | As needed | Effectively unlimited |

### Desktop / claude.ai constraints (from platform docs)

- Custom Skills on claude.ai are **per-user** (not org-shared).
- Network access: varies by user/admin settings. Can be full, partial, or none.
- Sandboxed code execution: available but not always active.
- Google Workspace (Calendar, Gmail, Drive) available as standard integrations.
- No `allowed-tools` enforcement on Desktop — that field is Claude Code-specific.

### Security note (from platform docs)

Skills should only be used from trusted sources. Skills have access to all integrations
the user has connected. Malicious skills can read Gmail, Calendar, Drive, etc.

## Web search supplement (for the two 403 URLs)

### From "Claude Skills: The Complete 2026 Guide" and code.claude.com/docs/en/skills:

- Desktop skills do NOT support `allowed-tools`, `disable-model-invocation`, `$ARGUMENTS`,
  or `context: fork` — those are Claude Code-only frontmatter fields.
- Description must be **third person** and **trigger-rich**: Claude under-fires skill
  activation, so descriptions should name multiple trigger phrases.
- Desktop skills upload as a zip file via Settings > Features in claude.ai.
- The folder structure is: `<skill-name>/SKILL.md` (and optionally `<skill-name>/icon.svg`,
  additional `.md` reference files).
- `name` in frontmatter must match the folder name.
