## Key Sections (from platform.claude.com/docs — successfully fetched)

### Skill structure

Every Skill requires a `SKILL.md` with YAML frontmatter:

```yaml
---
name: your-skill-name              # max 64 chars, lowercase/hyphens only
description: Brief description ... # max 1024 chars, non-empty
---
```

Required fields: `name` and `description`.

### Three-level content loading

- **Level 1 — Metadata** (always loaded, ~100 tokens): YAML frontmatter only
- **Level 2 — Instructions** (loaded when triggered, <5k tokens): SKILL.md body
- **Level 3 — Resources** (loaded on-demand, unlimited): bundled files, scripts

### Desktop (claude.ai) constraints

- Custom Skills: upload as ZIP via Settings > Features
- Individual user only; not org-wide
- Network access: varies by user/admin settings
- Code execution environment available (sandboxed)
- No `allowed-tools`, `disable-model-invocation`, or `$ARGUMENTS` for Desktop skills

### Sharing scope

- claude.ai: per-user, must re-upload per surface
- Claude Code: filesystem-based (`~/.claude/skills/` or `.claude/skills/`)
- Claude API: workspace-wide

### Description field guidance (from platform docs + SKILLS_GUIDE.md)

- Third person ("Researches…", not "I research…")
- Include trigger keywords — Claude under-fires on skill activation
- State both *what* the skill does and *when* to use it
- "Use when X, Y, or Z" pattern strongly encouraged
