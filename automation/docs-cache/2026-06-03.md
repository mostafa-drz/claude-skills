## Key Sections from platform.claude.com/docs/en/agents-and-tools/agent-skills/overview

### Skill Structure (required fields)

Every Skill requires a `SKILL.md` file with YAML frontmatter:

```yaml
---
name: your-skill-name          # max 64 chars, lowercase + hyphens only, no "anthropic"/"claude"
description: >-                # non-empty, max 1024 chars, no XML tags
  Brief description and when to use it.
---
```

Only `name` and `description` are required in frontmatter.

### Three-level loading model

| Level | When Loaded | Token Cost | Content |
|-------|------------|------------|---------|
| Metadata | Always (startup) | ~100 tokens/skill | `name` + `description` from frontmatter |
| Instructions | When skill triggered | Under 5k tokens | SKILL.md body |
| Resources | As needed | Effectively unlimited | Bundled files executed via bash |

### claude.ai / Desktop sandbox

- **Varying network access** depending on user/admin settings
- Custom Skills are **individual per user** (not org-wide)
- Skills uploaded to claude.ai are **not** shared with the API or Claude Code

### Description best practices (from platform docs)

The `description` field should include both:
1. What the Skill does
2. When Claude should use it (trigger phrases)

Broad, keyword-rich descriptions fire more reliably because Claude under-fires on skill activation.

### Pre-built skills available

PowerPoint (pptx), Excel (xlsx), Word (docx), PDF (pdf) — available on claude.ai and the API.
