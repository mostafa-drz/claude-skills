### Key sections relevant to skill authoring

**Frontmatter — required fields**
- `name`: max 64 chars, lowercase letters/numbers/hyphens only, cannot contain XML tags or reserved words "anthropic"/"claude"
- `description`: non-empty, max 1024 chars, cannot contain XML tags. Must state WHAT the skill does AND WHEN to use it (trigger phrases). Injected into system prompt as Level 1 metadata (~100 tokens).

**Three-level loading model**

| Level | When | Token cost | Content |
|-------|------|-----------|---------|
| 1 — Metadata | Always, at startup | ~100 tokens/skill | `name` + `description` from YAML frontmatter |
| 2 — Instructions | When skill is triggered | Under 5k tokens | SKILL.md body |
| 3 — Resources | As needed | Effectively unlimited | Bundled files (scripts, reference docs) read via bash |

**Key authoring note:** Claude reads SKILL.md via bash when a skill fires. The description is the only content always in context — make it broad and trigger-keyword-rich so Claude fires the skill rather than handling the request natively.

**Platform differences relevant to Desktop skills (claude.ai)**
- Custom Skills are per-user only (not org-shared)
- Network access is variable: full, partial, or none depending on user/admin settings
- Skills uploaded to claude.ai are separate from API skills (not synced across surfaces)

**Security note from docs:** Skills run in the VM environment; treat like installing software from a trusted source. Review bundled files before using Skills from unknown sources.
