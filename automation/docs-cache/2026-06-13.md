## Key Sections — platform.claude.com/docs (retrieved 2026-06-13)

### Skill structure (required)

Every Skill requires a `SKILL.md` file with YAML frontmatter:

```yaml
---
name: your-skill-name
description: Brief description of what this Skill does and when to use it
---
```

**Required fields**: `name` and `description`

**`name` constraints**: max 64 chars, lowercase letters/numbers/hyphens only, no XML tags, cannot contain "anthropic" or "claude".

**`description` constraints**: non-empty, max 1024 chars, no XML tags. Should include what the Skill does AND when Claude should use it.

### How Skills load (progressive disclosure)

- **Level 1 (Metadata, always loaded)**: YAML frontmatter — ~100 tokens per Skill, loaded at startup into system prompt.
- **Level 2 (Instructions, on trigger)**: SKILL.md body — under 5k tokens, read via bash when triggered.
- **Level 3 (Resources, as needed)**: Bundled files (scripts, FORMS.md, etc.) — accessed only when referenced, effectively unlimited.

### Where Desktop/claude.ai Skills work

- **claude.ai Custom Skills**: Uploaded via Settings > Features. Available on Pro, Max, Team, Enterprise with code execution enabled. Individual per-user, not org-shared.
- **Claude Code Skills**: Filesystem-based at `~/.claude/skills/` or `.claude/skills/`. Not uploaded via API.

### Runtime environment (claude.ai)

- Varying network access depending on user/admin settings.
- Pre-built Agent Skills available for PowerPoint, Excel, Word, PDF.
- Google Workspace connectors (Gmail, Calendar, Drive) available to all users.

### Security note

Skills are trusted by the model. Only use from trusted sources. Audit all bundled files for unusual network calls or file access patterns.
