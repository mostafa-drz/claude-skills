## Key Sections from platform.claude.com/docs — Agent Skills Overview

### Skill structure (required)

Every Skill requires a `SKILL.md` with YAML frontmatter:

```yaml
---
name: your-skill-name          # max 64 chars, lowercase + hyphens only, no XML tags
description: Brief description  # non-empty, max 1024 chars, no XML tags
---
```

`description` should state both **what** the Skill does and **when** Claude should use it.

### How Skills load (progressive disclosure)

| Level | When Loaded | Token Cost | Content |
|-------|-------------|------------|---------|
| Level 1: Metadata | Always (startup) | ~100 tokens per Skill | `name` + `description` from frontmatter |
| Level 2: Instructions | When Skill is triggered | Under 5k tokens | SKILL.md body |
| Level 3+: Resources | As needed | Effectively unlimited | Bundled files read via bash |

Claude loads SKILL.md **only when triggered** — the description is all that's in context at startup. This means descriptions must be broad and trigger-keyword-rich (Claude under-fires on skill activation).

### Where Skills work

- **claude.ai Desktop / claude.ai**: Custom Skills uploaded as zip. Individual user scope; not shared org-wide.
- **Claude Code**: Filesystem-based (`~/.claude/skills/`). Full network access.
- **Claude API**: Upload via `/v1/skills` endpoints. Workspace-wide scope.

### Runtime constraints for claude.ai Desktop

- Network access: varies by user/admin settings (may be full, partial, or none)
- Google Workspace available when connected via Settings
- MCP servers connectable via Desktop settings

### Pre-built Skills (not relevant to custom authoring)
