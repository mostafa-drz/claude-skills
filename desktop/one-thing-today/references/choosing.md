# Choosing the one thing

Contents: [Gather](#gather) · [Pick](#pick) · [Write it](#write-it) · [Learning](#learning)

## Gather

**Window:** today, plus anything due or happening before noon tomorrow. Look back 7 days
for threads that are waiting on the user. Older than that is context, not a candidate,
unless memory says it's a standing goal.

Pull what signals *pressure* or *importance*, and skip the rest:

| source | pull | ignore |
|---|---|---|
| Calendar | today's meetings that need prep; deadlines; free blocks long enough to work in | recurring stand-ups with nothing to prepare |
| Email | threads where someone asked the user for something and has no reply; dated asks | newsletters, notifications, receipts |
| Slack / Teams | direct asks and mentions with no answer; threads the user promised to follow up on | channel chatter |
| Linear / Jira / GitHub | items assigned and in progress, blocked on the user, due soon; reviews requested | backlog |
| Todoist / tasks | due today or overdue; priority 1; tasks the user keeps rescheduling | someday lists |
| Notion / Drive / Docs | docs the user edited recently and left unfinished; docs someone shared for review | everything else |
| Meeting notes (Granola, Fathom, Zoom) | action items the user took in the last week | the rest of the transcript |
| Memory | stated goals, what the user said matters this month, what works for them | |
| Past chats | earlier one-thing-today runs and their outcomes; plans made in chat | |

Tool names differ by surface and connector. Use what's there. Read in parallel, keep a
short candidate list (5–12 items), each with its source and a one-line fact. **Never
include message bodies or private details in the candidate list you show.**

## Pick

Score each candidate on four questions. Don't compute a number to look rigorous. Rank by
the answers, and be able to say the winning answer in one sentence.

1. **Who's waiting?** Someone blocked on the user beats work only the user sees.
2. **What breaks if it slips a day?** A real, dated consequence (a meeting, a launch, a
   promise) beats a soft one.
3. **Does it compound?** Moves a stated goal, removes a recurring pain, or makes tomorrow
   easier. This is the 1% question.
4. **Has it been avoided?** Rescheduled three times, or "80% done" for days. Avoided
   important work is usually the right pick, and it's where perfectionism hides.

Then discount:

- **Busywork dressed as progress**: inbox zero, tidying, reorganising, tweaking a
  template. These go in `not_today`.
- **Too big to start today**: pick its first finishable slice instead ("draft the outline",
  not "write the report").
- **Out of the user's hands**: waiting on someone else isn't a focus. Nudging them might be.

**Weight what the user said matters** (memory, a correction yesterday) above what looks
urgent in the inbox. When nothing stands out, pick the smallest step on their most
important stated goal. On a day with nothing pressing, that is the right answer.

**Meetings aren't the one thing.** Preparing for one can be.

## Write it

- **focus**: an imperative with a concrete object and, when it has one, a person. ≤90
  characters. "Send the pricing draft to Priya", not "Make progress on pricing".
- **why**: 2–3 sentences, plain, the way a thoughtful colleague would put it. Name the
  consequence. No hype, no "crucial", no "unlock".
- **evidence**: 1–4 lines, each `{source, fact}`. `source` is exactly a name from
  `sources_checked`, or `You`, `Memory`, `Past chats`. Facts are short and specific: a
  subject line, a meeting time, a status.
- **how**: 1–3 steps, each one physical action ≤140 characters with `minutes`. The first
  is ≤25 minutes and names the exact thing to open.
- **done_when**: something you could check. **good_enough**: the bar, plus what to skip.
- **not_today**: up to 3 things that looked tempting and can wait.
- **yesterday**: `{focus, outcome}` with outcome `done`, `partial`, `not_done` or `unknown`.

## Learning

Memory is the only thing that carries across days, so write to it deliberately and
sparingly. What to save:

| save | example | when |
|---|---|---|
| the run | "One thing 2026-09-24: send pricing draft to Priya" | every run |
| the outcome | "…: done" | when the user tells you or you can see it |
| a correction | "Board deck outranks client email this month" | whenever the user overrules the pick |
| a pattern | "Morning focuses get done; afternoon ones slip" | only after it has happened 3 times |
| a stated goal | "Q4 goal: ship the pricing page" | when the user says it |

Rules:

- **A correction beats a pattern.** When the user says "not that", save the reason and use
  it tomorrow.
- **A single outcome is a note. A repeat is a pattern.** Promote only after three.
- **Keep it short.** A handful of lines per week, not a diary. Merge rather than append
  when a pattern is restated.
- **Nothing sensitive.** No email contents, no health details, no names beyond first
  names already in the focus.
- **Tell the user what you saved**, in one line. They can say "forget that".
